# Backend memory (lessons learned; agents append, retro curates)

- Stack: Python 3.10, pytest, ruff. Run checks with `bash scripts/ci.sh`.
- Block (don't guess) when a card has no measurable criteria ("fast enough", "looks good"), names an ETL/source that doesn't exist in the repo, or has an empty `## Out of scope`. Ask: target/baseline numbers, exact report fields, format + output location, scope limits.
- Re-block when user answers are non-answers ("yes", "the output the user wants"): quote the answer, restate the question with concrete options and a fill-in form (N rows / X seconds, file path, field list). Phrase questions so "yes" cannot answer them (no yes/no questions). Card 002 hit this three times (7 questions each round, answers stayed vague or grew scope: "port any database", "countdown", "requirements").
- After 2 blocked rounds, stop re-asking everything: write a concrete proposed v1 into the card (e.g. stdlib, SQLite->SQLite, stdout text report with rows read/written/rejected + duration, no threshold) and ask the user only to reply "approve" or edit named lines. Ask at most 3 questions, the ones that truly block building. Card 002 still got 7-8 questions in rounds 3-6 (rule ignored, 6 blocks, 0 attempts used); obey this from round 3 on. Put the proposal in `## Plan`/criteria, not only in questions, so the user can approve with one word.
- Answers can arrive shifted/misaligned (card 002 round 6: answer to Q3 was "Output Channel: stdout", Q5 was "Testable Checks:"). Don't re-ask all; accept what is clearly usable (stdout JSON, keys rows_read/rows_written/problems/total_duration_seconds), treat the rest as unanswered, and fill them with stated defaults (`--db`, `--table` required args; problem types malformed row/duplicate key/type mismatch; duration = JSON field; a live stderr countdown is extra scope, so a separate card).
- Once answers exist in `## Answers`, the agent must fold them into the card itself (rewrite `## Acceptance criteria` and `## Out of scope` as testable lines, e.g. "ETL on sample .sql prints JSON with rows_read, rows_written, problems, total_duration_seconds") instead of blocking because the old criteria are still vague. Block only on facts still missing. Card 002 round 7 blocked on exactly this ("criteria still hold the original text, please replace them") and asked the user to edit the card: never hand the user card-editing chores or re-ask answered items (Out of scope list, keys, stdout).
- Don't ask the user for things the agent can create: write the sample `.sql` fixture (e.g. `tests/data/sample.sql`, 3 INSERT lines), pick N and the table name from it, and define `problems` entry fields (`type`, `row`, `message`, `fix`) with fixed fix text per type. State these as defaults in the card; user only overrides. Card 002 reached 8 blocks / 0 attempts because these were asked instead of decided. Round 8 still asked sample path, fix texts, JSON types and countdown meaning as a/b/c menus: when the answer to an open detail is "you choose", pick option (a), write it into the card, and go to PLAN. A menu of options is still a question; a decision stated in the card is not.
- The splitter/planner cannot edit the user's criteria, so if an answered card still has vague criteria, put the confirmed checks in `## Plan` as the criteria for each child and return SPLIT/PLANNED; never block on "please replace the criteria".
- Bare-token answers (".sql", "sqlite", "json") name a type, not a path/schema: next round ask for the file path, table name, and what the file holds (statements to run vs data to extract). Better: propose defaults (`data/source.sql`, `data/etl.db`, table `people`, report JSON to stdout) in the card and ask for approval.
- Treat user answers that add scope ("any database", live countdown, requirements file) as new scope: push to separate cards, not the first version.
- Card bundling several deliverables (build ETL + speed target + report): ask to split once the info is clear; also confirm that touching `main.py` is in scope.
- Use per-word `capitalize()` over `str.title()` (apostrophe quirk); pytest finds root-level modules without config.
- Ruff isort runs in CI: stdlib imports (e.g. `decimal`) go before `import pytest` in tests.
- Parse money with a strict fullmatch regex, not strip-and-replace: replacing '-', '(', ')' anywhere silently flips signs ("R$ -10", "10-5").
- Parser plans: specify the accepted grammar up front (sign only at start or after `R$`, balanced parens, digits only so "1e5"/"Infinity" fail) and add tests for malformed input ("R$ -10,00", "(10,00", "10-5", "1e5"), not just the card's happy cases. Card 003 was rejected once for this.
- Dates: guard with a strict ASCII fullmatch regex before `strptime`, which accepts "5/3/2024" and padded input.
- CPF: ASCII fullmatch `\d{3}\.?\d{3}\.?\d{3}-?\d{2}` with re.ASCII rejects Arabic-Indic digits and trailing "\n".
- Dedupe: index row[key] (not .get) so missing keys raise KeyError; test a later row lacking it.
- Multi-file bash heredocs can fail here ("Parser skipped input"); create files with the Write tool.
- Elapsed counter: compute duration once in `finally`, set Event, join thread, write final `\relapsed: {d:.3f}s` from that same value; test splits stderr on `\r` and compares to `f"{d:.3f}"`.
- Slugify: NFKD + `encode("ascii","ignore")` strips accents without deps.
- Reviewers reject unquantified wording ('fast enough') even when the card says no threshold: reword the criterion to the measurable part, and test live ticks by monkeypatching a slow step (sleep).
